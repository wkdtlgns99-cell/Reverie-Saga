## Selected behavior

The director selected manual refresh of the latest committed working progress and explicitly resumed native Unity verification on this workstation for this screen. The view is a separate dockable editor panel under `Reverie/현재 월드 보기 (읽기 전용)`. It reads the O3 knowledge profile. It does not start PlayRoom or a game owner. Opening and pressing `새로고침` request a single snapshot from a short-lived Python reader. Reading a valid loaded branch follows `game.sqlite.active.json`. The UI clears the previous snapshot while refreshing and on error. A source that is absent, busy, changed, invalid or incompatible produces a visible failure and supports retry. A concurrent write can make the read temporarily unavailable. No retry loop or clock advancing action is sent to Python.

`python -m app.world_observer [--working PATH]` reads the active knowledge working file using registered pins and SQLite read-only validation. The default shares the launcher path. `--working` supplies a base path for an isolated test or explicit inspection. Stdout is a single UTF-8 JSON document with format `reverie-world-observer/v1`, integer game tick and revision, current location, quest status/progress, and local resident IDs/names/roles with at most 8 chronological player-visible exchanges per NPC. Empty history is represented by an empty array. Show only speech/reply whose scheduled end is at or before the committed tick. Quest progress uses the active supply record and player inventory. At the quest city show stage, carried repair crates, the resolved tick if completed, and the current player-facing supply status. Outside that city show its location and a local availability message. While moving with no local contact, return no residents. NPC prompts, unshared rumors, judgment metadata, branch paths and hidden world state are absent. An active reference change during the read returns `WORLD_VIEW_CHANGED`. Missing files return `SAVE_NOT_FOUND`. Validation errors return a stable code on stderr and no stdout. No sidecar creation, slot load, recovery or provider access is performed by the reader.

Unity launches the repository Python without shell or command input, polls asynchronously, bounds output and runtime, validates the DTO version, and paints text with the existing Windows Korean font convention. Refresh and local resident selection are the only controls. The panel shows its game tick and revision. A failed refresh clears stale data. Closing it cancels its owned process only.
