## Findings

**P2-1: Quest boot validation fails open when `rules_document` has no `quest` key** (`orchestration/serialization.py:173`)
- **Problem:** `if "quest" not in bundle.rules_document: return` skips the whole check, including the uninitialized-constructor guard.
- **Probe:** I deleted the `quest` key from a real `quest_bundle` and `state_io` accepted it. I then also bound the presenter to different dialogue text and it was still accepted. The control with the key intact rejects with `presenter:quest.presenter:mismatch`.
- **Skipped constructor:** with the key absent, a skipped-constructor engine leaks a raw `AttributeError` from the scenario guard instead of a `BootstrapError`.
- **Risk:** low in practice, since bundles are built in app code, but the guard should be tight.
- **Repair:** detect quest presence from the quest-prefixed engines, schemas and presenters, and require `("quest" in rules_document) == present`. Add a test for the key-absent case.

**P2-2: A crashed process permanently wedges the call-budget ledger** (`adapters/generation_budget.py:119`)
- **Problem:** `_write` opens `budget.pending` with `"xb"`, and cleanup only runs after that open succeeds. A stale `.pending` left by a kill or power loss makes every later `reserve` raise `GENERATION_BUDGET_UNAVAILABLE`.
- **Probe:** I planted a `.pending` file and the next reserve failed. Deleting it by hand restored service.
- **Safety:** this fails closed, so it is not a budget bypass, but it is not self-healing.
- **Repair:** while holding the lock, call `pending.unlink(missing_ok=True)` before opening. `publish_fresh` has the same pattern, but it is recoverable by hand.

**P3 items**
- **Intent order is not enforced by the response schema** (`gemini_dialogue.py:57`): `decode_candidate` requires the exact order `completion, gratitude, offer, reminder`, but the schema only requires 4 lines drawn from the intent enum. A reordered response burns one of the two daily attempts and returns `GENERATION_OUTPUT`. Repair: sort lines by `INTENTS` in `parse_response` before validating, hashing the normalized bytes.
- **Approval is a label at load time** (`quest_dialogue.py:67`): `output_sha256` and `brief_sha256` are only format-checked, and `compile_dialogue` never checks the brief hash against `harbor_brief()`. In Unity, the expected catalog hash comes from `REVERIE_UNITY_QUEST_SHA256`, the same environment as the catalog (`PlayRoom.cs:50`). The real gate is the pinned catalog hash plus the prep-time `compile_dialogue`. I'd document it that way rather than call it authenticated approval.
- **Budget lock contention is reported as unavailability** (`generation_budget.py:51`): the lock is non-blocking. In my probe of 6 simultaneous processes there was 1 success and 5 `GENERATION_BUDGET_UNAVAILABLE`, never more than the cap of 2, so there is no bypass. A short bounded retry would avoid misleading failures.
- **HTTP error mapping is coarse** (`gemini_transport.py:59`): all other 4xx codes, including 400 and 404, map to `REJECTED`, and TLS or DNS errors map to `TIMEOUT`. Gemini commonly returns 400 for an invalid key, which would not be labeled `AUTH`. I did not verify that against the live service.
- **Hard-coded component count** (`orchestration/quest.py:360`): `len(core.components) != 11` is brittle. Derive it from the watch policy.
- **Unguarded Unity selectors:** the `LiveVerification` and malformed-frame hooks are correctly under `#if UNITY_EDITOR || DEVELOPMENT_BUILD`. The environment selectors in `PlayRoom.Start` are not gated. The README calls this a local development harness, so I'd note it rather than treat it as a defect.

## Answers to the seven focused questions

1. **Required-role boot validation:** yes, apart from P2-1. It enforces the exact role set, including `component:quest.progress`. Uninitialized instances raise `AttributeError` on `quest_content` and are caught, whether or not `isinstance` passes on this Python. The parametrized test covers the engine, checkpoint, adapter, presenter, admission, reducer, patch, payload and component roles.
2. **Check split:**
   - **Codec:** accepts any `before < after`.
   - **Single-step and net checks:** `stage` accepts only the single steps 0→1, 1→2 and 2→3, and `compose` and `validate_net` allow the net set plus 0→2.
   - **Forged 0→3 and 1→3:** both are rejected.
   - **Checkpoint:** requires exactly one quest record and canonical ordering. It rejects stage 1 with a dead target, and stage 2 or 3 with a living one.
   - **Limit:** a checkpoint cannot prove history, since stage 3 with a dead enemy looks honest. That relies on the persisted-diff checks, and `test_forged_persisted_completion_diff_rejected_through_real_io` covers it.
3. **Retry and recovery:** I read the post-commit path in `_present`, which logs the failure and adds a `PRESENTATION_FAILED` diagnostic without rolling back. The uncertain-recovery, precommit-preservation and postcommit tests pass here. I did not re-derive the durable layer.
4. **Pins and provider isolation:**
   - **Pins:** the behavioral pin comes from `rules["dialogue"]`, which holds the lines, `artifact_id` and the two hashes. Reviewer, timestamp and usage live only in the receipt or metadata and never enter it.
   - **Isolation:** a grep found no Gemini, `urllib`, `subprocess`, `socket` or `http` imports in `app` (apart from `dialogue_prepare.py`), `orchestration`, `engines`, `contracts` or `domain`. `lint-imports` reports 3 contracts kept.
5. **Transport and budget:** I read the transport code directly. It sets `ProxyHandler({})`, raises on redirects, passes the key over stdin, sanitizes errors with `from None` and discards stderr. The parent kills the child on any `BaseException`. Reconcile is idempotent via the `settled` set. The weak points are P2-2 and the contention behavior above.
6. **Request and API coherence:** the stdlib JSON parsing, nullable thought usage and the two explicit free-tier and data-use flags are coherent.
   - **Confirmed:** the model ID `gemini-3.5-flash-lite` and its MINIMAL thinking level are in current docs, and the code does not set temperature, top-K or top-P, which that model rejects.
   - **Still unverified:** free-tier availability and quota for this model, the enum casing of `thinkingLevel` (MINIMAL is the default, so I'd drop the field), support for `responseJsonSchema` keywords like `additionalProperties`, `minItems` and `maxItems`, and the 400-versus-401/403 behavior for a bad key.
7. **Client paths:** `act("talk")` raises `QUEST_UNAVAILABLE` without quest content and the worker maps that code. `retry` resends the same command and attachment token, and `load` clears `_previous`. I did not execute the Tk or Unity paths.
